# Hey, I'm keensummit10512

I spend most of my time writing Python scripts that make repetitive tasks disappear. Whether it's cleaning up logs, syncing data between services, or watching directories for changes, automation is the part of coding I enjoy the most.

Linux is where I feel at home. My daily workflow lives in the terminal — shell scripts, systemd units, and the occasional Makefile when things get more structured. I prefer tools that stay out of the way and just work.

## What I focus on

- **Python** — scripting, small utilities, and glue code that holds larger systems together
- **Automation** — turning manual processes into reliable, scheduled jobs
- **Linux** — system configuration, process management, and keeping servers lean
- **APIs** — consuming and occasionally building simple REST endpoints so tools can talk to each other

I like solutions that are readable six months later. That usually means clear function names, minimal dependencies, and comments only where the "why" isn't obvious from the code.

## How I work

Most of my projects start as a one-off script that solves an immediate problem. If it proves useful, I clean it up, add a few tests, and put it somewhere I can find it again. I care more about maintainability than clever one-liners.

When I'm exploring a new idea, I usually prototype in a notebook or a single file first. Once the approach feels solid, I break it into modules. I keep an eye on resource usage — especially memory and I/O — because a lot of my scripts run on modest hardware.
